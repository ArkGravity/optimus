# Optimus v0.1.0

The first versioned Optimus release packages the capabilities below. Release automation prepares a draft with verified artifacts; publication follows review of that draft. The Release page and its Actions run provide the publication and artifact verification record.

## Included capabilities

The initial versioned release packages the implemented main feature set:

- Authentication, RBAC, menus, audit records and encrypted credential vault.
- Read-only Kubernetes resource inspection and log streaming.
- Helm application/release management.
- Read-only AWS EC2/VPC/Security Groups/RDS, Aliyun ECS/VPC/Security Groups/RDS and GCP Compute/VPC/firewall/Cloud SQL inventory.
- Provider-specific credentials and scopes, shared resource lists/details, asynchronous/manual and scheduled sync, and sync history.
- Embedded English/Simplified Chinese Vue UI with light/dark themes and workspace tabs.
- One Go binary or a PostgreSQL 17 Docker Compose stack; Linux amd64 and arm64 packaging.
- MIT License.

Assets menus are Cloud Accounts, VPCs, Firewalls, Instances, Databases and Sync Runs. Dashboard and Observability Center are Coming Soon placeholders. Cloud inventory provides no cloud write/manage APIs.

## Compatibility warning

This version uses the fresh migration baseline ending at 00019: 31 business tables plus Goose history. Existing historical 00022, 00023 or 00028 databases cannot upgrade in place with these renumbered migrations. Recreate the actual database, including Goose history, only after stopping writers and securing a tested backup with the matching vault key and application configuration. Recreating containers alone retains data. Down migrations drop data and are not recovery. See [recovery](https://github.com/ArkGravity/optimus/blob/v0.1.0/docs/operations/recovery.md).

Once published, migrations are immutable; the next new migration is 00020. Legacy-invalid GCP credential records remain representable but require valid Service Account JSON before collection.

## Acceptance and release verification

The operator confirmed real AWS, Aliyun and GCP acceptance of `main-1bbb8fe` on 2026-11-05. This report does not assert a new production deployment environment. It is separate from the earlier 2026-10-28 production acceptance of `d0016d0` / historical schema 00022, whose inventory was AWS-only.

Historical implementation verification is recorded in the [multi-cloud plan](https://github.com/ArkGravity/optimus/blob/v0.1.0/docs/superpowers/plans/2026-10-28-multicloud-assets.md). It does not substitute for verification of the exact v0.1.0 release outputs.

Release validation requires the selected main revision's full CI, native amd64/arm64 archive execution, exact deployment-archive and image smoke, manifest/configuration equality in both registries, anonymous manifest reads and final checksums. Consult the linked Actions run and attached IMAGES.txt/SHA256SUMS for the actual results, and review the draft before publication. The [release guide](https://github.com/ArkGravity/optimus/blob/v0.1.0/docs/development/releases.md) defines the sequence. Release preparation does not deploy to a Production environment.
