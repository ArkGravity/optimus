# Optimus v0.1.2

Container Management with verified Linux release artifacts. This version carries
the functionality accepted for v0.1.1 and repairs the CI tests that prevented
its artifact delivery. The existing v0.1.1 source Release remains unchanged.

## Included changes

- Direct sidebar navigation replaces global workspace tabs; only the active
  data page is mounted.
- **Container Management / 容器管理** contains **Kubernetes** and **Docker**.
- Kubernetes has **Clusters, Nodes, Namespaces, Workloads, Network, Storage and
  Configs** buttons. The redundant heading card is removed to leave room for data.
- Resource kinds switch at the top right of each list. Configs offers
  **ConfigMap / Secrets**; Storage provides read-only **PV / PVC / StorageClass**.
- Docker remains an empty page reserved for future functionality.
- Existing Kubernetes permissions and permission-checked legacy URLs are
  preserved. Obsolete list/detail/Secret-reveal responses are discarded after
  scope changes or navigation.

## Delivery fixes

- Update the RBAC integration test to the `containers` menu group and its
  Kubernetes/Docker children.
- Exercise nanosecond timestamp precision explicitly and compare the persisted
  custom-role grant before/after seed, preserving the assertion that seed never
  rewrites custom grants.
- Use the normal release sequence: all six exact-main CI jobs, annotated tag,
  native amd64/arm64 image/archive/Compose smoke, registry publication, draft
  verification and formal publication. No release gate is bypassed.

## Installation and upgrade

The release workflow produces these six attachments:

- `optimus_v0.1.2_linux_amd64.tar.gz`
- `optimus_v0.1.2_linux_arm64.tar.gz`
- `optimus_v0.1.2_deploy.tar.gz`
- `INSTALL.md`
- `IMAGES.txt`
- `SHA256SUMS`

Versioned image references are `ghcr.io/arkgravity/optimus:v0.1.2` and
`docker.io/logic3579/optimus:v0.1.2`, with Linux amd64/arm64 platforms. Use the
attached `INSTALL.md`, `IMAGES.txt` and `SHA256SUMS` for installation and digests.

This version preserves the published schema19 baseline. Existing v0.1.0/v0.1.1
head19 databases require no recreation. Keep the existing vault key and
configuration. Historical 00022/00023/00028 databases still require the separately
documented [recovery procedure](https://github.com/ArkGravity/optimus/blob/v0.1.2/docs/operations/recovery.md).

After updating the application, run `optimus seed` with the existing
configuration to refresh built-in menus and built-in role grants. Original
Kubernetes parent/Clusters menu IDs, custom descendants and custom role grants
are preserved. Reserved menu-code collisions stop seed atomically.

Custom roles need explicit `k8s:storage:read` and `docker:environment:read` grants.
Kubernetes credentials need list access to PersistentVolumes,
PersistentVolumeClaims and StorageClasses for storage inventory. No Docker
management API or Kubernetes write API is added.

## Verification and scope

The [v0.1.2 release record](https://github.com/ArkGravity/optimus/blob/main/docs/superpowers/plans/2026-11-12-v0.1.2-release.md)
tracks the exact source, CI, native runtime tests, attachment checksums and
registry digests. Local implementation tests and operator acceptance remain
separate from verification of the exact versioned artifacts. No Production
deployment or application database operation is part of this release.
