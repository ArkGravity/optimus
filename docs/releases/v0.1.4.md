# Optimus v0.1.4

Docker host, image and container management over SSH, plus Inventory UX polish.
This version includes the changes on main since verified v0.1.3. Existing
v0.1.0–v0.1.3 tags, releases, images and attachments remain unchanged. The
operator confirmed Production acceptance of this revision before publication.

## Included changes

- **Container Management / Docker** manages remote Docker Engines through SSH
  to each host's Unix socket (default `/var/run/docker.sock`). Hosts support
  SSH key or password authentication; passwords are vault-sealed and never
  returned. See [Docker operations](../operations/docker.md).
- Host create/edit probes the connection before save. Image list/delete/prune
  and container list/inspect/start/stop/restart/delete run against the selected
  host. HostPicker never auto-selects.
- Permissions: `docker:environment:read` for lists and connection tests;
  `docker:environment:write` for host mutations and Engine write actions.
  Live SSH key references refuse credential deletion (`44001`).
- Additive migration `00021_create_docker_hosts.sql`. Existing head20 databases
  upgrade in place; then run `optimus seed` so admin/editor receive the write
  grant and the Docker menu stays wired.
- **Inventory UX:** Cloud Accounts show Provider first (label Provider /
  云服务商). VPC rows open detail only from Native ID. Instance, database,
  firewall and VPC details share a Back control. Every inventory filter bar
  (including Cloud Accounts and Sync Runs) has Reset.

Asset HTTP contracts and migrations 00001–00020 are unchanged aside from the
additive 00021 Docker hosts table.

## Installation and upgrade

The release workflow produces these six attachments:

- `optimus_v0.1.4_linux_amd64.tar.gz`
- `optimus_v0.1.4_linux_arm64.tar.gz`
- `optimus_v0.1.4_deploy.tar.gz`
- `INSTALL.md`
- `IMAGES.txt`
- `SHA256SUMS`

Versioned image references are `ghcr.io/arkgravity/optimus:v0.1.4` and
`docker.io/logic3579/optimus:v0.1.4`, with Linux amd64 and arm64 platforms.

Existing head19/head20 databases upgrade in place when migrate applies through
00021. Keep the current vault key and configuration. Historical
00022/00023/00028 databases still require the separately documented
[recovery procedure](../operations/recovery.md).

After updating the application, run `optimus seed` with the existing
configuration so built-in Docker menu grants and role bindings stay current.
Custom roles need an explicit `docker:environment:write` grant for mutations.
