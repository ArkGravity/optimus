# Optimus v0.1.1

Container Management and a more compact single-page workspace.

## Changes

- Replace global workspace tabs with direct sidebar navigation and one active data page.
- Rename the Kubernetes sidebar group to **Container Management / 容器管理**, with **Kubernetes** and **Docker** children.
- Consolidate Kubernetes into seven permission-aware sections: **Clusters, Nodes, Namespaces, Workloads, Network, Storage and Configs**. Remove the redundant heading card to make more room for data.
- Move resource-type switches to the top right of each list. Configs offers **ConfigMap / Secrets**; Storage offers read-only **PV / PVC / StorageClass** inventory.
- Reserve an empty Docker page for future container-management work.
- Preserve existing Kubernetes permissions and permission-checked legacy URLs. Reject stale list, detail and Secret-reveal responses after changing resources, clusters or pages.

## Updating an existing installation

This version preserves the v0.1.0 schema19 baseline and requires no database recreation for an existing v0.1.0 database. Published migrations are unchanged.

After updating the application, run `optimus seed` with its existing configuration to refresh built-in menus and built-in role grants. The update preserves the original Kubernetes parent/Clusters menu IDs, custom descendants and custom role grants. Reserved menu-code collisions stop seed atomically.

Custom roles need explicit grants for `k8s:storage:read` and `docker:environment:read`. Kubernetes credentials also need list access to PersistentVolumes, PersistentVolumeClaims and StorageClasses to browse storage resources. Docker remains an empty page and exposes no management API.

## Publication scope

The operator accepted the functionality and requested direct formal publication without waiting for or reviewing CI results or release artifacts. This is a **source release**, with GitHub-generated source archives. It has no attached Linux binaries, deployment archive or checksum manifest, and does not assert availability of `v0.1.1` registry images.

Earlier local checks passed 315 frontend tests, frontend lint/typecheck/locale/build, affected Go race/database suites, normal/tagged lint and generated-artifact checks. The final heading-removal follow-up passed its three existing navigation tests and frontend checks/build. These are local implementation results, not verification of v0.1.1 release artifacts.

No Production deployment or application database operation is part of this release.
