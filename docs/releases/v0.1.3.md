# Optimus v0.1.3

Inventory navigation, compact asset filters, and native GKE authentication.
This version includes the changes on main since verified v0.1.2. Existing
v0.1.0–v0.1.2 tags, releases, images and attachments remain unchanged.

## Included changes

- **Assets Management / 资产管理** has one sidebar child, **Inventory / 资产清单**.
  Cloud Accounts, VPCs, Firewalls, Instances, Databases and Sync Runs switch
  inside that page. Lists stay cross-account and keep provider and account
  filters.
- Each section has a direct URL under `/assets/inventory/<section>`. Detail
  URLs stay at `/assets/vpcs/:id`, `/assets/instances/:id`,
  `/assets/databases/:id` and `/assets/firewalls/:id`, and still highlight
  Inventory. Legacy list URLs check their existing permission and forward to
  the matching section.
- VPC, firewall, instance and database filters keep Provider, Cloud Account,
  search and Include deleted on the first row. Project, region, zone and
  family-specific fields open from **More filters**. The Firewalls list no
  longer shows the configured-rule inventory notice.
- Include deleted remains available for every inventory family. A successful
  full sync, cloud-account deletion or removed region can soft-delete VPCs,
  firewalls, databases and instances.
- Native GKE authentication uses an existing GCP Service Account Cloud Key.
  No kubeconfig upload or `gke-gcloud-auth-plugin` is required. See
  [GKE connections](../operations/gke.md).

Asset permission codes, asset HTTP APIs and migrations 00001–00019 are
unchanged. Migration `00020_gke_kubernetes_credentials.sql` is additive.

## Installation and upgrade

The release workflow produces these six attachments:

- `optimus_v0.1.3_linux_amd64.tar.gz`
- `optimus_v0.1.3_linux_arm64.tar.gz`
- `optimus_v0.1.3_deploy.tar.gz`
- `INSTALL.md`
- `IMAGES.txt`
- `SHA256SUMS`

Versioned image references are `ghcr.io/arkgravity/optimus:v0.1.3` and
`docker.io/logic3579/optimus:v0.1.3`, with Linux amd64 and arm64 platforms.

Existing head19 databases upgrade in place when migrate applies 00020. Keep
the current vault key and configuration. Historical 00022/00023/00028
databases still require the separately documented
[recovery procedure](../operations/recovery.md).

After updating the application, run `optimus seed` with the existing
configuration. Seed renames the Cloud Accounts menu to Inventory in place,
moves custom children, and retires the old VPC, firewall, instance, database
and sync-run menu rows. Custom roles keep their existing assets grants. A
reserved menu-code collision rolls the seed transaction back.
