# Documentation

Optimus is one repository: the Go backend at the root and the Vue web UI in
`web/`, shipped as a single `optimus` binary with the UI embedded.

## Reference

- [API specification](api/swagger.json): generated by `make swag`; also served
  at `/swagger/index.html`.
- [Permission catalog](permissions.md): generated by `make dump-perms` from
  `internal/infra/permissions/codes.go`.
- [Workspace layout and menu tabs](workspace-tabs.md): navigation, state
  retention and lifecycle rules for the compact workspace.
- [Brand mark](branding.md): the shared logo asset.
- Runtime smoke checklists: [P3](../scripts/p3-smoke.md),
  [P4 AWS](../scripts/p4-smoke.md), [P4 multi-cloud](../scripts/p4-multicloud-smoke.md).

## Designs and plans

[Specifications](superpowers/specs/) and
[implementation plans](superpowers/plans/) are named `YYYY-MM-DD-<topic>`.
Backend and frontend documents from the former split repositories are merged
here; the monorepo merge itself is described in
[2026-09-24-monorepo-single-binary-design.md](superpowers/specs/2026-09-24-monorepo-single-binary-design.md).

Historical documents keep their original paths, commands and commit IDs. Read
them with this mapping:

- `optimus-be/` is the repository root; `optimus-fe/` is `web/`.
- `deploy/` and the split-era frontend `Dockerfile`/`nginx.conf` are replaced by
  the root `Dockerfile` and `docker-compose.yml`; the binary serves the UI.
- `cmd/server`, `cmd/migrate`, `cmd/seed` and `cmd/vault-keygen` are
  subcommands of `cmd/optimus` (`optimus server|migrate|seed|vault-keygen`).
- The Go module is `github.com/ArkGravity/optimus` (formerly `optimus-be`).
- Pre-split commit IDs refer to the deleted original `logic3579/optimus`
  monorepo and do not resolve here. Split-era backend and frontend history is
  preserved in this repository.

Use the current README and AGENTS commands; old steps are implementation
history.

## Menu contract fixture

[`menu-contract.json`](../web/src/test/fixtures/menu-contract.json) records the
supported backend menu components, paths and permissions. It is test data, not
the runtime menu source. When backend menus change (`internal/seed`,
`/api/v1/me/menus`), update the fixture in the same change and run the web
tests.
